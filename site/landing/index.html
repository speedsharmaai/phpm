18x faster warm installs than Composer. Byte-identical vendor/.

An extremely fast, Composer-compatible PHP installer, written in Rust. It reads your composer.json and composer.lock unchanged and writes the same vendor/, byte for byte, in a fraction of the time on every install that is not bound by the network.

Install View on GitHub See the live sweep

Early, built in the open. phpm install is byte-identical to Composer on 98.1% of a 312-project nightly sweep, and its warm installs beat Composer's on every project measured on Linux and macOS. Windows isn't supported yet (open issues, help welcome). It installs from a lockfile only: no update or require yet. why phpm

Why a second tool, when Composer is good

Composer is good: a lockfile, parallel downloads, one blessed registry, a respected maintainer team. The question was never "is Composer slow" — it is "where is it slow enough that someone would install a second tool."

01

It never breaks a project

Every competitor either refuses plugins, emulates a few, or breaks silently. phpm installs natively when it can prove the result is identical to Composer's, and hands the rest to real Composer when it cannot — --explain says which. A user should never be worse off for having tried it.

02

Compatibility is published, not claimed

A nightly sweep diffs phpm's vendor/ against Composer's across hundreds of real projects and publishes the number, the way Ruff published ">99.9% Black-compatible." See Compatibility.

03

It is built for where installs multiply now

Agents run installs in CI, in containers, and in parallel git worktrees, each wanting its own vendor/. With a shared store, a new worktree's vendor/ costs a fraction of a second and almost no disk.

The sweep is also how real bugs get found before users hit them: it caught a case where, on filesystems without copy-on-write cloning, a plugin writing into a hard-linked file could corrupt the shared package store for every later install. phpm now copies instead of hard-linking whenever scripts or plugins will run.

vendor/ is also byte-identical, bytes and file modes, on every one of the project's own pinned fixtures (Laravel, Symfony demo, Monica, Bedrock, drupal/recommended-project, and two production apps), including the optimised class map.

Install

Prebuilt binaries for macOS and Linux are on every GitHub release. Windows isn't supported yet; the gaps are filed as issues.

macOS and Linux
$ curl -LsSf https://github.com/speedsharmaai/phpm/releases/latest/download/phpm-installer.sh | sh
Homebrew or source
$ brew install speedsharmaai/phpm/phpm
$ cargo install --locked --git https://github.com/speedsharmaai/phpm --tag v0.1.1 phpm

Then run it against a real project:

terminal
$ cd /path/to/your/php/project
$ phpm install --explain
Installing 109 packages...
109 native, 0 handed to Composer. vendor/ identical.

--explain prints, per package, whether it was installed natively or handed to Composer and why. Plain phpm install otherwise behaves like composer install: --no-dev, --no-scripts, --no-plugins, --optimize-autoloader / -o, --classmap-authoritative / -a all work.
